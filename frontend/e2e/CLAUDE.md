# E2E testing (Playwright) — Logjam

`@playwright/test` lives in `frontend/`. Config `playwright.config.ts`, specs here in `e2e/`. Run: `npm run e2e` (headless), `npm run e2e:ui` (interactive).

- **Real-Cognito auth-lifecycle spec** (`auth-lifecycle.spec.ts`) covers sign-in → consent gate → session persistence against a real pool. Env-gated — skips unless `E2E_AUTH_BASE_URL` + `E2E_TEST_EMAIL` + `E2E_TEST_PASSWORD` (a confirmed **staging** account) are set. No committed creds (privacy rule). Sign-up/confirm + token refresh are operator extensions documented in the spec header.
- **Browser = system Google Chrome** via `channel: "chrome"`. Playwright's bundled chromium/firefox/webkit binaries are unsupported on the ubuntu 26.04 dev host (`does not support chromium on ubuntu26.04-x64`), so `npx playwright install` fails — don't rely on it. Chrome-only on host; use the Playwright Docker image for cross-browser. Playwright cannot drive system Firefox regardless (its "firefox" engine is a patched build, not the system install).
- **Target via `E2E_BASE_URL`** (default `http://localhost:5173`). Config auto-starts the Vite dev server with `VITE_AUTH_MODE=fake` for local runs only; it does NOT start api/infra — bring those up first (`make dev` + `cd api && npm run dev`). Local fake-auth boots straight into the map (no login). **A second local server runs without fake auth** (`SIGN_IN_URL`, default `http://localhost:5199`) — fake auth sets "authenticated" on mount, so the sign-in screen is unreachable on every other target, and that server is the only place `SignIn` renders. It needs no API: every sign-in state is client-side until submit.
- **Prod runs are unauth-only** (`E2E_BASE_URL=https://logjamnsw.com`): assert the sign-in screen renders, nothing more. Privacy rule — no committed credentials, no private user data exercised against prod. Don't add a credentialed prod login flow without explicit sign-off.
- **The a11y spec (`a11y.spec.ts`) is the per-surface gate** — 23 cases over every page, dialog and sheet, four of them at 390. Three rules keep it honest:
  - **Narrow a long list before axe walks it.** axe is per-element and a list is one row repeated: the 311 places in the dev account cost 7.4s a walk against 0.17s for two, same result. Search the page down first (its hero, chip rails and row menu all survive). The Places case was 51.7s and failing the 60s cap on load until it did.
  - **A case never writes to the account.** The importer case stops at the confirm step rather than pressing Import; the consent gate stops with Agree armed rather than pressed (`recordConsent` PATCHes the account); CSV fixtures live in `e2e/__fixtures__/` and are synthetic, never a real place (the committed-fixture privacy rule).
  - **A `page.route` stub is how a state the dev stack cannot reach gets rendered** — an empty `/places` opens the first-login offer, a rewritten `consentVersion` on `GET /users/me` opens the gate. Stub the field the decision READS and leave the rest of the response real (`route.fetch()` first), so the case cannot pass against a payload the API would never send.
- **The RopeWiki load is unexercised, and it is not an oversight.** `importFromRopeWiki` has exactly two callers (`OnboardingChoiceDialog`, `PlacesPanel`) and both bulk-WRITE places into whichever account is signed in — there is no read-only path to it, and the two a11y cases that reach its surfaces stop before the row. Its dev prerequisite is easy to miss as well: the API reads the `reference/` snapshot out of the MiniStack media bucket, so a stack brought up with `docker compose up -d postgres ministack` (which skips `make _ministack-tf`) answers 503 rather than importing anything. Exercising it means a real write to the dev account and a `make reset` after — which orphans a paired phone's mirror (root `CLAUDE.local.md`). Decide before running it, not after.
- **MCP:** `@playwright/mcp` (also `--browser chrome`) is registered in root `.mcp.json` so Claude can drive a live browser in-session. Lets Claude verify UI changes interactively against local dev or prod.
